Why Mahfooz Mobile

Built around the moment it actually matters

Every control below exists because of a specific, real failure mode — not as a generic checklist.

Ownership verification

A block is only honored after confirming the reporter is the device's verified owner — preventing malicious blocking of someone else's phone.

Encrypted identity data

CNIC and other identifiers are encrypted at rest and masked everywhere in the interface, minimizing exposure of sensitive identifiers.

Tamper-evident audit trail

Every block and unblock action is logged in a hash-chained, append-only trail — so disputed actions can always be traced and investigated.

Instant, no-login reporting

The Emergency PIN flow needs no password and no app — just your CNIC and PIN, from any browser, on any device.

Automated theft report

A reference document is generated the moment your device is blocked, routed to a police contact point to support a real FIR filing.

Security by design

Designed for CY321 Secure Software Design

Every control here maps to a documented threat, not a generic best-practice list.

Argon2id + TOTP

Passwords hashed, never reversible. Authenticator-app MFA — no SMS gateway, no per-message cost.

Anti-enumeration

Lookup endpoints are rate-limited and return generic responses — no leaking who owns what.

Separate DB roles

Device-status writes and audit-log writes use different, least-privilege database credentials.

Common questions

Is this the official PTA system?

No — Mahfooz Mobile is an independent university security-design project and is not affiliated with PTA or NADRA.

What if I forget my Emergency PIN during an emergency?

An automated 5-question recovery flow, plus a physical backup code you store at home, both get you back in without needing a live agent.

What happens to my CNIC data?

It's encrypted at rest and masked everywhere in the interface — except where law enforcement needs the full value on a theft report.
